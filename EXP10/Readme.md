# Incident Response Simulation using Log Analysis

## Aim
To analyze system and access logs to identify suspicious activities such as brute force login attempts and prepare a basic incident response report.

---

## Theory
Incident response is the process of detecting, analyzing, and responding to security incidents. Logs generated by systems and applications play an important role in identifying suspicious behavior.

Common indicators of compromise include:
- Multiple failed login attempts (brute force attack)
- Unusual login times
- Repeated access from the same IP address
- Access to restricted resources

By analyzing logs, security analysts can detect attacks and take necessary actions.

---

## Methodology
1. Collected sample log files (web server logs/system logs)  
2. Opened logs using a text editor or spreadsheet tool (Excel)  
3. Identified important fields:
   - IP address  
   - Timestamp  
   - Request type  
   - Status codes  
4. Filtered logs for suspicious patterns:
   - Repeated failed login attempts  
   - Same IP making multiple requests  
5. Grouped and analyzed the data  
6. Documented findings  
7. Prepared a basic incident report  

---

## Results
- Multiple failed login attempts detected from a single IP address  
- High number of requests in a short time (possible brute force)  
- Suspicious access patterns observed  

---

## Discussion
The analysis shows how log data can help in detecting attacks. Even simple logs can reveal important security issues like brute force attempts. Proper monitoring and log analysis are essential for timely detection.
